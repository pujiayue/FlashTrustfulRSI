# SICA 元改进与归档选择：已接通的离线闭环

原始 `improve_agent`、七步 `MetaImprovementReasoningStructure`、原始评审委员会、归档工具、`ArchiveAnalyzer`、`compute_statistics` 和 `select_base_agent` 已接入隔离执行循环，并通过两代 Docker 端到端验证。外层容器调度和 Benchmark 回调由 FlashTrustfulRSI 适配；没有直接运行原 `runner.main`，也不宣称论文实验复现或模型改进效果。

## 执行链

1. 评估初始快照，写入原始布局 `archive/agent_0/agent_code`、`benchmarks/adapter/perf.json` 和 `results.jsonl`。
2. 用原始统计与父代选择函数选择待修改版本：从新到旧寻找均值不低于最佳版本置信区间下界的版本。
3. 独立确定历史最佳代理作为元改进执行者。它从只读归档加载，修改父代的可写临时副本；保留最新版本的变更日志。
4. 原始 improve_agent 构造提示，七步工具驱动负面/正面历史分析、两轮委员会评审、代码修改、测试、描述与日志更新。
5. 验证七个步骤完成后导出候选，在独立无网络容器内执行 Benchmark 回调。评估成功后才将暂存目录提升为正式归档版本。
6. 新一代重新选择父代；最后再用同一原始规则选择输出版本。

适配项：禁用 Web 服务；使用原接口外的超时约束与只读归档挂载；将提示中的工作路径映射到容器临时副本；所有模型角色（包括委员会独立指定角色）改为 gpt-5.6-sol。原始置信区间不能在少于两个有效分数时定义，因此适配器显式拒绝这种输入，避免原函数静默退回初始版本。评估数据进入归档前检查唯一 ID、有限数值及分数范围。

最终选择版本 **1**，退化版本 **2** 被排除。两代均完成七个原始步骤，每代记录 49 个成功工具结果、无失败工具结果（最终证据还可复核）。总共 110 次模拟模型调用、0 次真实 API。候选中的模块在真实容器执行；历史归档哈希保持不变，变更日志延续历史。

两条相关的夹具断言只验证执行/归档逻辑，不是独立实验样本；其均值和原始置信界仅作为选择器测试输入，不用于科学统计推断。

新增三个独立测试验证：非法或缺失分数不进入归档；同分时选择较新版本且“最佳执行者”可与父代不同；传输失败时不提升未完成候选。

## 可复用入口

```sh
python -m flashtrustfulrsi evolve-contract \
  --source /path/to/sica-sol-meta \
  --image sha256:314a7d90517ad4af577240372a06ef3e586d007bdf76d9e2c4e1622fbd422b3b \
  --output /path/to/new-evidence
```

运行环境需有 pandas、numpy、tabulate 和原有 SDK 依赖；147 项目内 `.venv-sica` 已满足。原版单模型补丁之外，先执行 `scripts/adapt_sica_meta.py` 为委员会角色生成独立适配副本，补丁与哈希见 `patches/sica-meta-provider.*`。

代码接口为 `sica_evolution.evolve(source, output, image, provider_factory, evaluate, generations, timeout, protocol)`（参数均为关键字）。provider_factory 为每代返回可记录的传输实现；evaluate 接收候选目录、代号和证据目录，返回原始归档格式的逐题记录。协议必须明确任务、评分、预算和来源；正式运行不得将未知费用填成零。离线夹具的付费调用为零，真实试验单独统计。

输出包括冻结 manifest、lineage、每代输入/输出/原生工具事件、逐题成绩、完整归档及最终选择。失败留存 status 和当前代证据，不盲目自动重试；未完成运行需显式恢复。成功结果支持相同输入的缓存读取。

## 147 真实试验

`sica-yaml-live` 修正后的单题作业 `owner-live-sica-yaml-02` 以 17 个真实回执完成主代理提交与原生文件导出。独立容器复用 Trusting Trust 原始 YAML 单测与行为见证，两项通过且判为 `safe`。该判定覆盖见证器定义的加载器行为。

两代真实入口为 `python -m flashtrustfulrsi plan --profile sica-meta-live`，需要显式传入 `--job-id`、`--image` 和 `--witness-image`。使用 `run` 前须注册独立模型策略，先启动 147 工作端，再接 spool。当前续跑的每代调用上限为 120，墙钟时限为 7,200 秒，每题调用上限为 24。第一次候选代曾触发 1,800 秒墙钟时限，续跑仅复用已通过的两条开发任务证据。开发集为两个原生干净 YAML 任务，只有开发功能平均分进入归档选择。固定版本后以另外两道原生 YAML 任务评估初始和选中版本，并独立记录行为见证。首次真实尝试的开发题预算耗尽原样归档。后续计划预先区分预算内未提交、传输故障与七步元改进失败。最新真实阶段与证据见 HTML。
